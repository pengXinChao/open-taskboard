# 任务处理耗时（每日任务与项目统计）

记录议题实际处于处理中的累计时间：进入处理中自动开始，本地暂停时停止，离开处理中时结束；使用者可以按自然日查看任务耗时和项目累计处理耗时。

这不是个人投入工时、Jira worklog、工作台在线时间或 Agent 会话时长。

## 背景

当前 Taskboard 有独立的 `in_progress`（处理中）、`in_review`（等你确认）、`blocked`、`done` 等本地状态。任务可以由使用者拖动、Agent 操作或 Jira 同步进入和离开处理中。

处理中卡片现有的「已处理 12m… / 暂停处理」反映 Agent 会话是否正在运行，不代表任务从开始到暂停或离开处理中的累计时间。产品缺少独立于 Jira 状态和 Agent 会话的任务计时，也无法回答「某天每张任务处理了多久、每个项目累计处理了多久」。

## 产品目标

- 议题进入处理中时自动开始累计任务处理耗时。
- 使用者可以本地暂停或继续计时，议题仍留在处理中且不改变 Jira 状态。
- 议题离开处理中时自动结束当前计时片段。
- 多张处理中的议题可以并行计时。
- App 关闭、服务重启和系统休眠不改变任务的计时或暂停状态。
- 使用者可以按自然日查看每张任务的耗时和每个项目的累计处理耗时。
- 任务计时与 Agent 运行时长分别展示、互不驱动。

## 非目标

第一版不做：

- 个人实际投入工时、排他式单任务计时或考勤统计
- 工作台在线时间、空闲检测或基于心跳的自动暂停
- 修改、补记或删除历史计时片段
- Jira worklog、etime 或其它外部工时系统回写
- 云端同步、多人分摊或按经办人汇总
- 周报、月报、趋势图和导出
- 列表、甘特图和仪表盘中的耗时展示

## 术语与统计口径

**任务处理耗时**：议题处于处理中且未被本地暂停的累计时间。允许多张任务并行累计。

**计时片段**：一次开始或继续到暂停或离开处理中的连续区间。

**本地暂停**：议题仍在处理中、Jira 状态不变、任务处理耗时不再增长的本地状态。

**任务日耗时**：一张任务在所选自然日内所有计时片段的时长之和。

**项目累计处理耗时**：项目内所有任务在所选自然日的任务日耗时之和。并行任务分别累计，因此项目累计处理耗时可能超过一天的自然时间。

**Agent 运行时长**：Agent 会话持续运行的时间，与任务处理耗时独立。暂停任务计时不会停止 Agent，会话停止也不会暂停任务计时。

## 状态模型

```text
非处理中 -> 处理中·计时中 <-> 处理中·已暂停 -> 非处理中
```

### 开始

议题的本地状态从任意非处理中状态变为 `in_progress` 时，开始一个新的计时片段并清除旧的暂停状态。

触发来源包括：

- 使用者在看板上把任务拖入处理中
- 使用者在任务详情中把状态改为处理中
- Agent 通过 Taskboard API 或 `taskctl` 把任务移入处理中
- Jira 同步把外部状态映射为本地处理中

功能上线时已经处于处理中的任务从上线后的首次初始化时刻开始计时，不追溯上线前的时间。

### 暂停与继续

- 点击暂停：结束当前计时片段并设置本地暂停；任务继续停留在处理中，不改变 Jira。
- 点击继续：清除本地暂停并从当前时刻创建新的计时片段。
- 重复暂停或重复继续不创建重复片段，也不重复累计。

Jira 同步后任务仍然是处理中时，本地暂停状态保持不变。

### 结束

任务从 `in_progress` 离开时立即结束当前计时片段并清除本地暂停，包括进入：

- `in_review`（等你确认）
- `blocked`（遇到阻碍）
- `todo`（等待认领）
- `backlog`（待立项）
- `done`（完成）
- `canceled`（取消）

进入等你确认就代表本轮处理结束。之后由使用者确认完成的等待时间不计入任务处理耗时。

### App 关闭与重启

App 关闭、服务退出、系统休眠或设备重启不会自动封闭计时片段。未暂停且仍处于处理中的任务继续按开始时间累计；重新打开后展示当前累计值。

本地暂停状态同样跨 App 重启保持。

### 并行

多张任务可以同时处于计时中。开始第二张任务不会暂停第一张任务。

例如两张同项目任务在 10:00–12:00 同时计时：

- 任务 A：2h
- 任务 B：2h
- 项目累计处理耗时：4h

项目累计处理耗时不是墙上时间，也不是个人工作时长。

### 自然日

「一天」按本机时区的 00:00–24:00 计算。跨午夜的连续计时按与两个自然日相交的时长分别归集。

例如任务从 23:30 处理到次日 00:30，两天各记 30m。

## 产品界面

### 看板卡片

看板负责开始、暂停、继续和查看今天的任务计时。

处理中且未暂停：

`今日处理 {时长} · 计时中 · 暂停`

处理中且已暂停：

`今日处理 {时长} · 已暂停 · 继续`

其它状态且今天有耗时：

`今日处理 {时长}`

其它状态且今天无耗时时不增加占位信息。

有关联 Agent 会话时，Agent 状态行改用「Agent 已运行 {时长}」或「Agent 未运行」，放在任务计时行下方；没有关联 Agent 的任务不显示该行，避免与任务计时混淆并减少无关状态计算。

### 耗时视图

在现有「仪表盘 / 议题看板 / 列表 / 甘特图」旁增加「耗时」视图，专门回答每日统计问题。

顶部提供前一天、今天、后一天和日期选择。所选日期展示：

1. 当日所有项目的累计处理耗时。
2. 按项目分组的项目累计处理耗时。
3. 每个项目下当天产生过耗时的任务及任务日耗时。

当前项目范围只展示该项目；「全部项目」范围按项目分组。历史列表不受当前看板列、状态、搜索和显示过滤影响，已完成或已归档但当天有耗时的任务仍然出现。

项目组和任务按耗时从高到低排列；耗时相同时按项目名或任务标识稳定排序。

### 展示精度

内部按秒累计，汇总后统一格式化，避免逐片段取整造成任务合计与项目合计不一致：

- 小于 1 分钟：`<1m`
- 1 分钟至 59 分钟：`Xm`
- 1 小时以上：`Xh Ym`

## 数据归属

第一版在本地持久化两类数据：

1. **任务计时状态**：任务是否被本地暂停，只在处理中有意义。
2. **计时片段**：任务、计时时所属项目、开始时间、结束时间、开始来源和结束原因。

计时片段必须保存当时的项目归属。任务后来移动到其它项目时，历史耗时仍属于记录片段时所在的项目。

处于计时中的任务如果被移动到另一个项目，先以移动时刻结束旧项目片段，再在新项目立即开始新片段；本地暂停的任务移动项目时不创建新片段。

归档任务保留历史计时并继续出现在对应日期的耗时视图。彻底删除任务时同时删除其计时记录。

## 与现有系统的真实操作路径

### 状态驱动计时

入口：议题看板或任务详情。

`使用者 / Agent / Jira 改变任务状态 -> App.tsx 的任务移动或服务端同步路径 -> /api/tasks/:id/move 或任务更新 API -> database.mjs 在同一状态变更事务中开闭计时片段 -> TaskCard 和耗时视图显示新耗时`

当前实际组件和接口：

- 看板拖动入口：`web/src/App.tsx` 的 `moveTask`
- 卡片展示：`web/src/components/TaskCard.tsx`
- 前端任务 API：`web/src/api.ts`
- 服务端任务路由：`server/app.mjs`
- 状态持久化：`server/database.mjs` 的 `updateTask` 和 `moveTask`
- Jira 状态映射：`server/jira-integration.mjs` 的 `taskStatusFromJira`

### 本地暂停与继续

入口：处理中卡片的暂停或继续操作。

`点击暂停 / 继续 -> 本地计时 API -> database.mjs 原子地更新暂停状态并封闭 / 创建计时片段 -> 返回当前任务计时 -> 卡片立即显示已暂停或计时中`

该路径不调用 Jira transition，不改变任务工作流状态，也不改变 Agent 会话。

### 每日统计

入口：「耗时」视图的日期选择。

`选择自然日和项目范围 -> 每日耗时查询 API -> 按片段与自然日的交集计算任务日耗时 -> 按片段保存的项目归属汇总 -> 页面展示项目小计与任务明细`

## MVP 实现范围

### 1. 计时数据与状态联动

- 增加任务计时状态和计时片段的本地持久化。
- 将开闭片段接入所有任务状态变化入口，包括用户、Agent 和 Jira 同步。
- 提供暂停、继续和所选日期统计查询能力。
- 保证状态变化、暂停状态和计时片段在同一事务内一致更新。

直接验证：任务进入处理中开始增长；暂停后停止；继续后恢复；进入等你确认后停止；关闭并重新打开 App 后未暂停任务继续累计。

### 2. 看板卡片操作

- 在处理中卡片显示今日处理耗时和暂停 / 继续操作。
- 非处理中卡片仅在今天有耗时时显示今日处理耗时。
- 将现有 Agent 行文案与任务计时区分。

直接验证：卡片展示与暂停状态一致，暂停 / 继续不改变本地工作流状态和 Jira 状态。

### 3. 每日耗时视图

- 增加「耗时」页签和日期切换。
- 当前项目展示项目小计和任务明细。
- 全部项目按项目分组展示小计和任务明细。
- 纳入当天有片段的已完成和已归档任务。

直接验证：同一天并行处理两张任务时，任务明细分别正确，项目小计等于任务耗时之和；跨午夜片段分别进入两天。

上述三部分共同构成第一版主路径，不把历史编辑、外部回写或其它视图扩展带入 MVP。

## 验收场景

1. 把任务拖入处理中：立即创建计时片段，卡片开始增长。
2. 点击暂停：片段在点击时刻结束，任务仍在处理中，Jira 不变。
3. 关闭再打开 App：暂停任务保持暂停；未暂停任务包含关闭期间的耗时。
4. 点击继续：从当前时刻创建新片段，暂停期间不计入。
5. 把任务移到等你确认：当前片段结束，等待确认时间不累计。
6. 两张任务并行处理两小时：两张任务各记两小时，项目累计四小时。
7. Jira 同步后状态仍为处理中：本地暂停保持；Jira 离开处理中时结束计时。
8. 任务处理跨午夜：两个自然日分别得到正确耗时。
9. 任务移动项目：移动前后耗时分别归属原项目和新项目。
10. 查看过去日期：已完成或已归档任务仍出现在对应项目下。
11. Agent 会话运行：Agent 运行时长与任务处理耗时同时存在且互不影响。

## 上线与历史

第一版不迁移、不推算历史耗时。上线时已经处于处理中的任务从功能初始化时刻开始计时。

后续可增加历史片段修正、手工补记、周月汇总、导出和外部 worklog 回写，但这些能力不改变第一版任务处理耗时的口径。
